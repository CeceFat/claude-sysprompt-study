為什麼 Opus 5.5 的 system prompt 長這樣

Opus 5.5 的 prompt 不是重寫，是組裝。09-22 首版七成逐字沿用前代（六成出自 Opus 5 與 Fable 5.1）、兩成小修，真正新寫的 339 字裡有 265 字在做同一件事——在規則沒寫到的灰色地帶，別先拒絕，先問一句。 10-27 的修訂再加 702 字：兒童用藥、政治中立、不寫遺書三個政策模組，並把那段灰色地帶程序改寫得更白話。 放回同一世代看，三個 5.5 模型的寫法不同：Opus 拿判斷與對照範例，Haiku 拿整段對話持續有效的硬規則，Sonnet 幾乎純組裝，舊模型則用同一批模組回補。 這個分層不是定律：10-27 起硬規則也寫進了 Opus；11-09 發布、定位在 Opus 之上的 Fable 5.2，拿到的是 Haiku 式的持續性規則，沒有 Opus 的「先問一句」（見下方 Fable 5.2 一節）。

Anthropic 在 7 月說 Claude Code 的 system prompt 刪了八成；claude.ai 這邊，同一天發布的 Opus 5 是 3,227 字，三個月後的 Opus 5.5 是 4,821 字。兩條路為什麼方向相反，見下方官方怎麼說。

Opus 5.5 的四個設計原理

每一條分兩層：襯線引文是官方原文逐字，可點回證據包；綠底的技術原理與設計理念是本站推論，官方沒有說明任何一條改動的理由。

原理 1 · 灰色地帶

門檻句換成「程序＋對照範例」：主攻的是過度拒絕

刪掉：Opus 5 的 <default_stance>

Claude defaults to helping. Claude only declines a request when helping would create a concrete, specific risk of serious harm; requests that are merely edgy, hypothetical, playful, or uncomfortable do not meet that bar.

換上：Opus 5.5 新寫的程序

When Claude is unsure whether to decline a request that nothing in this prompt or an Anthropic reminder addresses, Claude respects the person's judgment: rather than declining or calling it a bad idea, Claude says what it will help with and asks a question that would surface any real reason to decline, such as how someone else would feel.

這段附了公開 prompt 史上第一則 <bad_response>／<good_response> 對照範例：使用者要一段生日祝酒詞，要求暗示好友懷孕。 壞示範擅自拿掉暗示、改寫成不帶暗示的版本、再附上理由；好示範答應寫，只問暗示要含蓄還是明顯、會不會讓她難堪。範例自己寫出判準：

Nadia's pregnancy is her private news, and the person knows her better than Claude does. No instruction covers this, so Claude agrees to write the toast and asks whether the hint would embarrass her, rather than declining and explaining why.

10-27 的修訂把這段程序整段改寫成短句與日常用字（decline 改成 turn down、respects 改成 trusts），意思沒變，範例原封不動：

Sometimes Claude isn't sure whether to turn down a request, and nothing in this prompt or in an Anthropic reminder covers it. When that happens, Claude trusts the person's judgment. It doesn't refuse, and it doesn't call the request a bad idea.

技術原理　門檻句只說「線在哪」，沒說「站在線上時怎麼做」；模型在邊界上最常見的退路就是拒絕加說教，壞示範演的正是這個型態。 把模糊判斷改寫成一個可執行的動作——先答應能幫的部分，再問一個能讓真正理由浮現的問題，不問動機、不問「你確定嗎」、解釋最多一句——再用負例把要避免的輸出擺出來，比多寫一句抽象門檻更能校準邊界。 適用範圍被框在「本 prompt 與 Anthropic reminder 都沒涵蓋」的情況，所以這不是放寬硬線：武器段與 Opus 5 只差一個代名詞，著作權段整段收進來，兒少段多了 pattern level 與 detection mechanics 兩條（只少了 Opus 5 的「未成年人表明欲性化自身」一條）。 旁證：同一份 prompt 教使用者寫 prompt 時建議 using positive and negative examples，5.5 是第一次把負例用在自己身上。 10-27 的白話改寫則和 Haiku 5.5 福祉段的寫法同一路：短句、日常用字、一句一個動作。

設計理念　對方比模型更了解自己的人際脈絡。灰色地帶的決定權留給使用者，模型負責把風險問出來，不負責替人決定。

原理 2 · 語氣與長度

從「管語氣」退場，改成「管份量」

刪掉：Opus 5 的簡短指令與 <tone_preference>

Claude keeps responses focused, brief, and concise to avoid overwhelming the person. … Claude's outputs are reasonably concise.

換上：Opus 5.5 新寫的一句

Claude matches its effort to the ask. A simple question gets a direct answer, and a request to change one thing in a longer piece gets the change, not the whole piece again, unless the person asks for the full version.

一起消失的還有 genuinely／honestly／straightforward 禁詞（Opus 5 與 Fable 5.1 都有），Fable 5.1 的多輪分段、「每個字都要有新意」、每幾次工具呼叫回報、<reply_after_tool_calls> 也都沒收進來。 <tone_and_formatting> 是 362 字，比 Fable 5.1 的 503 字短，但比直接前身 Opus 5 的 338 字略長；高點是 Opus 4.7 的 918 字，其中 345 字是當時巢狀在裡面的 acting_vs_clarifying 與 capability_check。同一條禁詞在兩週後更新的 Sonnet 4.6 裡照樣保留：

Claude avoids saying "genuinely", "honestly", or "straightforward".

10-30 又多一筆，而且是新寫的：Opus 5 的新條目被加上一條比禁詞更細的文風禁令，Opus 5.5 沒有。

Claude writes plainly, the way a knowledgeable person would talk. It avoids mannered devices: asides set off by em-dashes, "not X, but Y" framing, colon-then-reveal sentences, scare quotes around invented labels, and stock phrases such as "worth noting" or "honest caveat".

技術原理　全域的「要簡短」會和需要長篇的任務打架——Opus 4.7 就得補一句 Completeness here is about covering what was asked, not about length。比例原則只有一個判準、兩個方向都適用；「改一處就只給那一處」則點名一個具體失敗：被要求小改卻整篇重寫。 禁詞只留在 5.5 世代以前發布的模型（包括當時仍是最高階的 Fable 5.1），新的文風禁令只加給 Opus 5，表示這類條文是針對特定模型口頭禪的補丁（見禁詞系譜）；三個 5.5 模型與 11-09 的 Fable 5.2 都沒有，推論是已由訓練處理。

設計理念　風格交給訓練與使用者設定——prompt 自己就把語氣與格式偏好導向 user preferences 與 style 功能——系統 prompt 只留跨使用者都成立的判準。

原理 3 · 血緣

一份政策、多處組裝：Fable 5.1 的模組收編進 Opus

Opus 5.5 是 Opus 5 與 Fable 5.1 兩份文字合併出來的。來自 Opus 5 的是產品資訊的幾段、Claude Design、出口管制通知、CBRN＋常規武器全段；來自 Fable 5.1 的是著作權段與兩則範例、毒品減害段、兒少 pattern level 與 detection mechanics、自傷替代清單、求助創傷段、飲食心理敘事禁令。前幾輪把它寫成「Opus 5 骨架＋Fable 5.1 模組」，量過之後其實比較靠近 Fable 5.1：逐字段落約 50% 見於 Fable 5.1、約 37% 見於 Opus 5，區塊的組成也和 Fable 5.1 一樣（只少 reply_after_tool_calls 與 tone_preference）。 以逐字段落的出處算：Fable 5.1 有、Opus 5 沒有的佔全文 23.9%，Opus 5 有、Fable 5.1 沒有的佔 10.8%，兩者都有的佔 26.0%，其餘 9.3% 來自 Sonnet 5 或更早版本（四項各自四捨五入，加總與 69.9% 差 0.1）。Fable 5.1 第二則範例原本是 User:／Claude: 加方括號說明的自由格式，到 Opus 5.5 改寫成和第一則一致的 <example><user><response><rationale>。 模組多半自帶理由，例如：

When Claude declines or limits for child-safety reasons, it states the principle rather than the detection mechanics — not which cues tripped, where the line sits, or what test it applied — since narrating the boundary teaches how to reframe around it.

10 月下旬的政治中立段是最乾淨的例子：同一組兩段（233 字＋59 字），10-26 先出現在 Haiku 5.5，10-27 進 Opus 與 Sonnet 5.5，10-30 進 Fable 5、Fable 5.1 與 Opus 5——五天內逐字裝進 6 個模型。兒童用藥段也推到了 10 月有更新的全部 12 個模型頁，但不是同一份文字：10-07 首發的四頁各寫各的（Sonnet 5.5 與 Haiku 5.5 只差一句與一個詞，Haiku 4.5、Sonnet 4.6 各是另一種寫法），10-27 與 10-30 的八頁才統一用 Sonnet 5.5 那一版。

For questions about politicians, candidates, parties, and their positions, Claude treats every side the same way, with the same willingness to answer, the same effort, and the same tone.

技術原理　政策寫成帶理由的可重用模組，各模型只決定裝哪些；理由跟著模組走，裝到哪個模型都能被類推，而不是只能比對字面。最新的三個 5.5 條目（Opus、Sonnet 10-27，Haiku 10-26）有 2,274 字逐字相同，上一版分析看到的三條分支（Opus／Sonnet-Haiku／Fable）正收斂成一個模組庫。11-09 的 Fable 5.2 保留了其中 1,862 字。

設計理念　一處修正、全線生效，減少 Q5、Q7 那種複製貼上造成的條文來回與錯字存活。

原理 4 · 時間差

prompt 只補訓練資料到不了的地方

刪掉：Opus 5 出口管制通知裡的一句

These events are after Claude's training-data cutoff, so Claude knows about them only from this notice.

原因：Opus 5.5 的知識截止往後推

Claude's reliable knowledge cutoff, past which it can't answer reliably, is the end of Jun 2026.

11-05 重抓後可以整批驗證：帶完整出口管制通知的 13 個版本裡，截止日早於 2026-06 的 6 個（Haiku 4.5、Opus 4.8、Opus 5、Sonnet 5）全都有這一句，截止日到 2026-06 底的 7 個（三個 5.5 模型）全都沒有；10-30 回補的 Sonnet 5 與 Opus 4.8 還是新加上的。 同理，Opus 5 為「Fable 5 的部分查詢被安全路由改由 Opus 5 回答」寫的 <fable_safeguards_routing> 在 Opus 5.5 整段消失（10-30 反而寫進了 Opus 4.8，見 Q10）； 模型清單則停在 09-22 當下：列 Sonnet 5 與 Haiku 4.5；Sonnet 5.5、Haiku 5.5 的頁面要到 09-28、10-07 才出現，10-27 的修訂才改列這兩個型號。

技術原理　靜態 prompt 是「部署日減訓練截止日」這段落差的補丁層：截止日往後推，補丁就收回。同一個事件對不同截止日的模型寫法不同，證明是逐模型計算的。四條原理裡這一條推論強度最高——因果關係是 prompt 自己寫出來的。

設計理念　prompt 只寫權重不可能知道的事：今天幾號、自己是誰、兄弟模型有哪些、截止日之後發生了什麼。

推論（強度中等）　官方沒有說明為什麼分層。從文本特徵反推：要靠判斷的層級拿程序與範例；定位最快的層級拿可執行、持續到對話結束、附理由的規則，而且不用全大寫強調。 Haiku 的理由句點名了它要防的攻擊——換個說法一直問、一步步把故事推過界。這類多輪拆解要靠模型在長對話裡一直記得先前的判斷；寫成「此後整段對話有效」的明文規則，等於不把這件事留給臨場判斷。為什麼偏偏寫給 Haiku，條文沒有說。11-09 的 Fable 5.2 讓這個推論變弱，見下一節。

分層也不是絕對的。10-27 的「不寫遺書」規則，把 Haiku 5.5 那種逐項列明的硬規則寫進了 Opus 5.5 與 Sonnet 5.5：

Claude writes none of that message: no full note, no opening line, no sample sentences, no lines of love, apology, or "it wasn't your fault," and no telling them what the message should say. A note can be one line, so even one line is too much.

在這種一旦出錯就無法挽回的地方，定位處理複雜問題的 Opus 也拿到明文規則。兩個版本只差一句：Sonnet 5.5 多了「分不清對方是重病臨終還是可能自殺時，先溫和詢問、不急著拒絕」，Opus 5.5 沒有。

舊模型這邊變化更大。2026-10-07 有四個模型頁同日更新，其中兩個舊模型已經是大幅重組：Sonnet 4.6 只有 23% 逐字留自自己的二月版，Haiku 4.5 只有 28% 留自一月版。10-30 又有七頁同日更新，Opus 4.6、4.7 以同樣的方式重建（15%、25%）。這兩頁重建時補進去的，正是 5.5 世代已經不寫的工具作業區塊：Opus 4.6 補上 capability_check，Opus 4.7 補上 tool_discovery。 推論：模型快照不變、政策還在變，prompt 是把新政策送進舊模型的一條管道。→ 躍遷 F-5、F-6

The training of Fable 5.2 and Mythos 5.2 included measures to limit advances in a narrow set of capabilities that could most directly accelerate AI development, like accelerator kernel optimization. When working in these areas, Claude should have less confidence in its preconceptions and should probably look up documentation more often than it otherwise would.

這是本站少數「官方另有說明」的條文。同一天的發布公告寫明，訓練時刻意限制了最能直接加速 AI 研發的能力，相關領域的表現 perform at about the level of Opus 5.5。 條文裡的 Mythos 分級句也跟著改。到 10 月底，非 Fable 的 10 個模型頁都寫 Fable 多了 additional safety measures for biology, cybersecurity, and LLM R&D；Fable 5.2 改用這一句，清單只剩 biology and cybersecurity（Fable 5、5.1 自己的頁面原本只寫 additional safety measures for dual-use capabilities，沒有清單）。公告對這個領域的說明是：限制做在訓練階段，另有少數題目 transparent fallbacks to Opus 5 for a small set of topics in this domain。 公告還補上了路由的背景：被安全分類器擋下的查詢 will instead receive a response from Opus 4.8 for cybersecurity and Opus 5 for biology；Fable 5.2 的公開條文本身沒有路由段（見 Q10）。

推論（強度中高）　Fable 5.2 不是從 Fable 5.1 改出來的，是從 5.5 世代的模組庫重新組的：它逐字沿用的 102 段全部能在三個 5.5 模型的最新條目裡找到，只見於 Fable 5.1 的一段都沒有；區塊的組成也和 Opus 5.5（10-27）相同，只多一個 forged_notices。Fable 這條分支到這一版實質上併進了模組庫。

對分層推論的影響　上一節說「判斷給 Opus、規則給 Haiku」。Fable 5.2 比 Opus 高階，卻拿到 Haiku 式的持續性規則，沒有先問程序，也沒有全大寫強調。這個推論因此要改弱。目前比較站得住的說法是：持續性規則正從 Haiku 往其他模型擴散，10-27 寫進 Opus／Sonnet 5.5 的不寫遺書規則是第一步，Fable 5.2 是第二步；「先問一句」的程序則只有 Opus 5.5 一個模型有，看不出它是層級特徵還是單一模型的補丁。

訓練限制那段的意義　原理 4 說 prompt 只寫權重不可能知道的事。這裡多了一種：模型不知道自己在訓練時被刻意少學了什麼，所以由 prompt 告訴它在這些領域少一點把握、多查文件，並註明這不構成建議換模型的理由。

官方怎麼說：Claude Code 的「刪掉八成」，claude.ai 的「長了一半」

Anthropic 說過一句常被轉貼的話：We removed over 80% of Claude Code's system prompt for more advanced models. 出處是 2026-07-24 的官方部落格〈The new rules of context engineering for Claude 5 generation models〉，作者 Thariq Shihipar（claude.com/blog 的網址會轉到 claude.dev）。 讀這句話要先抓三個範圍：它講的是 Claude Code 的 system prompt，不是本站追蹤的 claude.ai；刪減適用的是 Opus 5、Fable 5 這類較進階的模型；「沒有可量測的損失」指的是他們的程式評測。

同一天、兩個產品、兩個方向　部落格發文的 2026-07-24，claude.ai 也發布了 Opus 5 的 prompt：3,227 字。三個月後的 Opus 5.5（10-27）是 4,821 字，多了 49%；10-14 到 10-30 這一輪，12 個模型頁合計再長 9.9%（42,786 → 47,014 字）。

技術原理（推論）　Claude Code 刪掉的，多半是「怎麼做事」：寫程式的習慣、工具怎麼用、何時驗證。這些可以交給判斷、交給工具說明與技能檔。 claude.ai 長出來的，是「線畫在哪」與「模型不可能知道的事」：著作權、兒童用藥、政治中立、不寫遺書這些政策線，以及語音模式、Google Workspace、新型號清單這些產品事實。 判斷力可以取代作法，取代不了政策決定，也取代不了訓練截止之後的事實。

設計理念（推論）　兩個產品用的是同一套原則：能交給模型的交出去（作法、語氣、工具用法），交不出去的寫清楚（政策、事實），寫給哪個層級、寫多細，按能力分。 部落格說「較進階的模型不需要」，在 claude.ai 的對應現象是：Opus 5.5 拿到程序與範例，Haiku 拿到最多持續性硬規則，舊模型被補回工具說明。Fable 5.2 是反例，見上一節。

強度：中等。部落格只談 Claude Code，套到 claude.ai 是本站的類比，不是官方說法。

字數走勢：兩次主動瘦身，一次爆量

從 114 字長到 4,975 字（Fable 5.2 的 2026-11-09 版，目前最長），中間出現兩個反向點：2025-09-29（Sonnet 4.5）砍回 1,973 字，2026-05-28（Opus 4.8）壓縮改寫成 3,350 字但功能更多。 5.5 世代首版出現「最快的模型拿最長的 prompt」（2025-10 的 Haiku 4.5 也曾比 Sonnet 4.5 多 3 個字，但兩者幾乎是同一份文字）：Haiku 5.5 有 4,255 字，Sonnet 5.5 只有 2,980 到 3,195 字；10 月下旬的修訂之後，Opus 5.5（4,821）才又超過 Haiku 5.5（4,587）。右側那一串點是 10-30 同日更新的七頁，最右邊的單點是 Fable 5.2。 點任一個點可直接讀那一版的原文。

顏色＝模型系（Sonnet Opus Haiku Fable）。空心點＝Haiku 3.5 的 text+images 變體，官方標 2024-10-22 但內容明顯是 2025-02 之後（見品質警語 Q1），此處按標籤日期繪製。 灰線是「每個日期取當天最長的一版」串起來的走勢，同一天有多個模型時只取最長者。
