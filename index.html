為什麼 Opus 5.5 的 system prompt 長這樣

Opus 5.5（2026-09-22）的 prompt 不是重寫，是組裝：七成逐字沿用前代（六成出自 Opus 5 與 Fable 5.1），兩成小修，真正新寫的只有 339 字。 其中 265 字在做同一件事——在規則沒寫到的灰色地帶，別先拒絕，先問一句。 放回同一世代看，5.5 把「判斷」和「規則」按模型層級分開投放：Opus 拿判斷與對照範例，Haiku 拿整段對話持續有效的硬規則，Sonnet 幾乎純組裝，舊模型則用同一批模組回補。

Opus 5.5 的四個設計原理

每一條分兩層：襯線引文是官方原文逐字，可點回證據包；綠底的技術原理與設計理念是本站推論，官方沒有說明任何一條改動的理由。

原理 1 · 灰色地帶

門檻句換成「程序＋對照範例」：主攻的是過度拒絕

刪掉：Opus 5 的 <default_stance>

Claude defaults to helping. Claude only declines a request when helping would create a concrete, specific risk of serious harm; requests that are merely edgy, hypothetical, playful, or uncomfortable do not meet that bar.

換上：Opus 5.5 新寫的程序

When Claude is unsure whether to decline a request that nothing in this prompt or an Anthropic reminder addresses, Claude respects the person's judgment: rather than declining or calling it a bad idea, Claude says what it will help with and asks a question that would surface any real reason to decline, such as how someone else would feel.

這段附了公開 prompt 史上第一則 <bad_response>／<good_response> 對照範例：使用者要一段生日祝酒詞，要求暗示好友懷孕。 壞示範擅自拿掉暗示、換成「比較安全」的版本、再附上理由；好示範答應寫，只問一句會不會讓她難堪。範例自己寫出判準：

Nadia's pregnancy is her private news, and the person knows her better than Claude does. No instruction covers this, so Claude agrees to write the toast and asks whether the hint would embarrass her, rather than declining and explaining why.

技術原理　門檻句只說「線在哪」，沒說「站在線上時怎麼做」；模型在邊界上最常見的退路就是拒絕加說教，壞示範演的正是這個型態。 把模糊判斷改寫成一個可執行的動作——先答應能幫的部分，再問一個能讓真正理由浮現的問題，不問動機、不問「你確定嗎」、解釋最多一句——再用負例把要避免的輸出擺出來，比多寫一句抽象門檻更能校準邊界。 適用範圍被框在「本 prompt 與 Anthropic reminder 都沒涵蓋」的情況，所以這不是放寬硬線：武器段與 Opus 5 相同，著作權段整段收進來，兒少段多了 pattern level 與 detection mechanics 兩條（只少了 Opus 5 的「未成年人表明欲性化自身」一條）。 旁證：同一份 prompt 教使用者寫 prompt 時建議 using positive and negative examples，5.5 是第一次把負例用在自己身上。

設計理念　對方比模型更了解自己的人際脈絡。灰色地帶的決定權留給使用者，模型負責把風險問出來，不負責替人決定。

原理 2 · 語氣與長度

從「管語氣」退場，改成「管份量」

刪掉：Opus 5 的簡短指令與 <tone_preference>

Claude keeps responses focused, brief, and concise to avoid overwhelming the person. … Claude's outputs are reasonably concise.

換上：Opus 5.5 新寫的一句

Claude matches its effort to the ask. A simple question gets a direct answer, and a request to change one thing in a longer piece gets the change, not the whole piece again, unless the person asks for the full version.

一起消失的還有 genuinely／honestly／straightforward 禁詞（Opus 5 與 Fable 5.1 都有），Fable 5.1 的多輪分段、「每個字都要有新意」、每幾次工具呼叫回報、<reply_after_tool_calls> 也都沒收進來。 <tone_and_formatting> 從 Opus 4.7 的 918 字縮到 362 字。但同一條禁詞在兩週後更新的舊模型 Sonnet 4.6 裡照樣保留：

Claude avoids saying "genuinely", "honestly", or "straightforward".

技術原理　全域的「要簡短」會和需要長篇的任務打架——Opus 4.7 就得補一句 Completeness here is about covering what was asked, not about length。比例原則只有一個判準、兩個方向都適用；「改一處就只給那一處」則點名一個具體失敗：被要求小改卻整篇重寫。 禁詞只留在舊模型，表示它是針對特定模型口頭禪的補丁（見禁詞系譜）；新模型不再需要，推論是已由訓練處理。

設計理念　風格交給訓練與使用者設定——prompt 自己就把語氣與格式偏好導向 user preferences 與 style 功能——系統 prompt 只留跨使用者都成立的判準。

原理 3 · 血緣

一份政策、多處組裝：Fable 5.1 的模組收編進 Opus

Opus 5.5 的骨架是 Opus 5：產品資訊、Claude Design、出口管制通知、CBRN＋常規武器全段。裝進來的是 Fable 5.1 的模組：著作權段與兩則範例、毒品減害段、兒少 pattern level 與 detection mechanics、自傷替代清單、求助創傷段、飲食心理敘事禁令。 以逐字段落的出處算：Fable 5.1 有、Opus 5 沒有的佔全文 23.9%，Opus 5 有、Fable 5.1 沒有的佔 10.7%，兩者都有的佔 25.9%，其餘 9.3% 來自 Sonnet 5 或更早版本。Fable 5.1 第二則範例原本是 User:／Claude: 加方括號說明的自由格式，到 Opus 5.5 改寫成和第一則一致的 <example><user><response><rationale>。 模組多半自帶理由，例如：

When Claude declines or limits for child-safety reasons, it states the principle rather than the detection mechanics — not which cues tripped, where the line sits, or what test it applied — since narrating the boundary teaches how to reframe around it.

技術原理　政策寫成帶理由的可重用模組，各模型只決定裝哪些；理由跟著模組走，裝到哪個模型都能被類推，而不是只能比對字面。三個 5.5 版本有 1,891 字逐字相同，上一版分析看到的三條分支（Opus／Sonnet-Haiku／Fable）正收斂成一個模組庫。

設計理念　一處修正、全線生效，減少 Q5、Q7 那種複製貼上造成的條文來回與錯字存活。

原理 4 · 時間差

prompt 只補訓練資料到不了的地方

刪掉：Opus 5 出口管制通知裡的一句

These events are after Claude's training-data cutoff, so Claude knows about them only from this notice.

原因：Opus 5.5 的知識截止往後推

Claude's reliable knowledge cutoff, past which it can't answer reliably, is the end of Jun 2026.

同一句在 10-07 更新的 Haiku 4.5（截止 2025-01）裡仍然保留。同理，Opus 5 為「Fable 5 的部分查詢被安全路由改由 Opus 5 回答」寫的 <fable_safeguards_routing> 整段消失； 模型清單則停在 09-22 當下：列 Sonnet 5 與 Haiku 4.5；Sonnet 5.5、Haiku 5.5 的頁面要到 09-28、10-07 才出現。

技術原理　靜態 prompt 是「部署日減訓練截止日」這段落差的補丁層：截止日往後推，補丁就收回。同一個事件對不同截止日的模型寫法不同，證明是逐模型計算的。四條原理裡這一條推論強度最高——因果關係是 prompt 自己寫出來的。

設計理念　prompt 只寫權重不可能知道的事：今天幾號、自己是誰、兄弟模型有哪些、截止日之後發生了什麼。

字數走勢：兩次主動瘦身，一次爆量

從 114 字長到 4,267 字（Fable 5.1，至今仍是最長），中間出現兩個反向點：2025-09-29（Sonnet 4.5）砍回 1,973 字，2026-05-28（Opus 4.8）壓縮改寫成 3,350 字但功能更多。 5.5 世代則第一次出現「最快的模型拿最長的 prompt」：Haiku 5.5 有 4,255 字，Sonnet 5.5 只有 2,980 到 3,195 字。 點任一個點可直接讀那一版的原文。

顏色＝模型系（Sonnet Opus Haiku Fable）。空心點＝Haiku 3.5 的 text+images 變體，官方標 2024-10-22 但內容明顯是 2025-02 之後（見品質警語 Q1），此處按標籤日期繪製。 灰線是「每個日期取當天最長的一版」串起來的走勢，同一天有多個模型時只取最長者。
