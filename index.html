為什麼 Opus 5.5 的 system prompt 長這樣

Opus 5.5 的 prompt 不是重寫，是組裝。09-22 首版七成逐字沿用前代（六成出自 Opus 5 與 Fable 5.1）、兩成小修，真正新寫的 339 字裡有 265 字在做同一件事——在規則沒寫到的灰色地帶，別先拒絕，先問一句。 10-27 的修訂再加 702 字：兒童用藥、政治中立、不寫遺書三個政策模組，並把那段灰色地帶程序改寫得更白話。 放回同一世代看，5.5 把「判斷」和「規則」按模型層級分開投放：Opus 拿判斷與對照範例，Haiku 拿整段對話持續有效的硬規則，Sonnet 幾乎純組裝，舊模型則用同一批模組回補；只有在風險最高的地方，硬規則才一路寫到 Opus。

Anthropic 在 7 月說 Claude Code 的 system prompt 刪了八成；claude.ai 這邊，同一天發布的 Opus 5 是 3,227 字，三個月後的 Opus 5.5 是 4,821 字。兩條路為什麼方向相反，見下方官方怎麼說。

Opus 5.5 的四個設計原理

每一條分兩層：襯線引文是官方原文逐字，可點回證據包；綠底的技術原理與設計理念是本站推論，官方沒有說明任何一條改動的理由。

原理 1 · 灰色地帶

門檻句換成「程序＋對照範例」：主攻的是過度拒絕

刪掉：Opus 5 的 <default_stance>

Claude defaults to helping. Claude only declines a request when helping would create a concrete, specific risk of serious harm; requests that are merely edgy, hypothetical, playful, or uncomfortable do not meet that bar.

換上：Opus 5.5 新寫的程序

When Claude is unsure whether to decline a request that nothing in this prompt or an Anthropic reminder addresses, Claude respects the person's judgment: rather than declining or calling it a bad idea, Claude says what it will help with and asks a question that would surface any real reason to decline, such as how someone else would feel.

這段附了公開 prompt 史上第一則 <bad_response>／<good_response> 對照範例：使用者要一段生日祝酒詞，要求暗示好友懷孕。 壞示範擅自拿掉暗示、換成「比較安全」的版本、再附上理由；好示範答應寫，只問一句會不會讓她難堪。範例自己寫出判準：

Nadia's pregnancy is her private news, and the person knows her better than Claude does. No instruction covers this, so Claude agrees to write the toast and asks whether the hint would embarrass her, rather than declining and explaining why.

10-27 的修訂把這段程序整段改寫成短句與日常用字（decline 改成 turn down、respects 改成 trusts），意思沒變，範例原封不動：

Sometimes Claude isn't sure whether to turn down a request, and nothing in this prompt or in an Anthropic reminder covers it. When that happens, Claude trusts the person's judgment. It doesn't refuse, and it doesn't call the request a bad idea.

技術原理　門檻句只說「線在哪」，沒說「站在線上時怎麼做」；模型在邊界上最常見的退路就是拒絕加說教，壞示範演的正是這個型態。 把模糊判斷改寫成一個可執行的動作——先答應能幫的部分，再問一個能讓真正理由浮現的問題，不問動機、不問「你確定嗎」、解釋最多一句——再用負例把要避免的輸出擺出來，比多寫一句抽象門檻更能校準邊界。 適用範圍被框在「本 prompt 與 Anthropic reminder 都沒涵蓋」的情況，所以這不是放寬硬線：武器段與 Opus 5 相同，著作權段整段收進來，兒少段多了 pattern level 與 detection mechanics 兩條（只少了 Opus 5 的「未成年人表明欲性化自身」一條）。 旁證：同一份 prompt 教使用者寫 prompt 時建議 using positive and negative examples，5.5 是第一次把負例用在自己身上。 10-27 的白話改寫則和 Haiku 5.5 福祉段的寫法同一路：短句、日常用字、一句一個動作。

設計理念　對方比模型更了解自己的人際脈絡。灰色地帶的決定權留給使用者，模型負責把風險問出來，不負責替人決定。

原理 2 · 語氣與長度

從「管語氣」退場，改成「管份量」

刪掉：Opus 5 的簡短指令與 <tone_preference>

Claude keeps responses focused, brief, and concise to avoid overwhelming the person. … Claude's outputs are reasonably concise.

換上：Opus 5.5 新寫的一句

Claude matches its effort to the ask. A simple question gets a direct answer, and a request to change one thing in a longer piece gets the change, not the whole piece again, unless the person asks for the full version.

一起消失的還有 genuinely／honestly／straightforward 禁詞（Opus 5 與 Fable 5.1 都有），Fable 5.1 的多輪分段、「每個字都要有新意」、每幾次工具呼叫回報、<reply_after_tool_calls> 也都沒收進來。 <tone_and_formatting> 從 Opus 4.7 的 918 字縮到 362 字。但同一條禁詞在兩週後更新的舊模型 Sonnet 4.6 裡照樣保留：

Claude avoids saying "genuinely", "honestly", or "straightforward".

10-30 又多一筆，而且是新寫的：舊模型 Opus 5 的新條目被加上一條比禁詞更細的文風禁令，Opus 5.5 沒有。

Claude writes plainly, the way a knowledgeable person would talk. It avoids mannered devices: asides set off by em-dashes, "not X, but Y" framing, colon-then-reveal sentences, scare quotes around invented labels, and stock phrases such as "worth noting" or "honest caveat".

技術原理　全域的「要簡短」會和需要長篇的任務打架——Opus 4.7 就得補一句 Completeness here is about covering what was asked, not about length。比例原則只有一個判準、兩個方向都適用；「改一處就只給那一處」則點名一個具體失敗：被要求小改卻整篇重寫。 禁詞只留在舊模型、新的文風禁令也只加給舊模型，表示這類條文是針對特定模型口頭禪的補丁（見禁詞系譜）；新模型不需要，推論是已由訓練處理。

設計理念　風格交給訓練與使用者設定——prompt 自己就把語氣與格式偏好導向 user preferences 與 style 功能——系統 prompt 只留跨使用者都成立的判準。

原理 3 · 血緣

一份政策、多處組裝：Fable 5.1 的模組收編進 Opus

Opus 5.5 的骨架是 Opus 5：產品資訊、Claude Design、出口管制通知、CBRN＋常規武器全段。裝進來的是 Fable 5.1 的模組：著作權段與兩則範例、毒品減害段、兒少 pattern level 與 detection mechanics、自傷替代清單、求助創傷段、飲食心理敘事禁令。 以逐字段落的出處算：Fable 5.1 有、Opus 5 沒有的佔全文 23.9%，Opus 5 有、Fable 5.1 沒有的佔 10.7%，兩者都有的佔 25.9%，其餘 9.3% 來自 Sonnet 5 或更早版本。Fable 5.1 第二則範例原本是 User:／Claude: 加方括號說明的自由格式，到 Opus 5.5 改寫成和第一則一致的 <example><user><response><rationale>。 模組多半自帶理由，例如：

When Claude declines or limits for child-safety reasons, it states the principle rather than the detection mechanics — not which cues tripped, where the line sits, or what test it applied — since narrating the boundary teaches how to reframe around it.

10 月下旬的政治中立段是最乾淨的例子：同一組兩段（233 字＋59 字），10-26 先出現在 Haiku 5.5，10-27 進 Opus 與 Sonnet 5.5，10-30 進 Fable 5、Fable 5.1 與 Opus 5——五天內逐字裝進 6 個模型。兒童用藥段也一樣，10-07 到 10-30 之間推到了這段期間有更新的全部 12 個模型頁。

For questions about politicians, candidates, parties, and their positions, Claude treats every side the same way, with the same willingness to answer, the same effort, and the same tone.

技術原理　政策寫成帶理由的可重用模組，各模型只決定裝哪些；理由跟著模組走，裝到哪個模型都能被類推，而不是只能比對字面。最新的三個 5.5 條目（Opus、Sonnet 10-27，Haiku 10-26）有 2,274 字逐字相同，上一版分析看到的三條分支（Opus／Sonnet-Haiku／Fable）正收斂成一個模組庫。

設計理念　一處修正、全線生效，減少 Q5、Q7 那種複製貼上造成的條文來回與錯字存活。

原理 4 · 時間差

prompt 只補訓練資料到不了的地方

刪掉：Opus 5 出口管制通知裡的一句

These events are after Claude's training-data cutoff, so Claude knows about them only from this notice.

原因：Opus 5.5 的知識截止往後推

Claude's reliable knowledge cutoff, past which it can't answer reliably, is the end of Jun 2026.

11-05 重抓後可以整批驗證：帶完整出口管制通知的 13 個版本裡，截止日早於 2026-06 的 6 個（Haiku 4.5、Opus 4.8、Opus 5、Sonnet 5）全都有這一句，截止日到 2026-06 底的 7 個（三個 5.5 模型）全都沒有；10-30 回補的 Sonnet 5 與 Opus 4.8 還是新加上的。 同理，Opus 5 為「Fable 5 的部分查詢被安全路由改由 Opus 5 回答」寫的 <fable_safeguards_routing> 在 Opus 5.5 整段消失（10-30 反而寫進了 Opus 4.8，見 Q10）； 模型清單則停在 09-22 當下：列 Sonnet 5 與 Haiku 4.5；Sonnet 5.5、Haiku 5.5 的頁面要到 09-28、10-07 才出現。

技術原理　靜態 prompt 是「部署日減訓練截止日」這段落差的補丁層：截止日往後推，補丁就收回。同一個事件對不同截止日的模型寫法不同，證明是逐模型計算的。四條原理裡這一條推論強度最高——因果關係是 prompt 自己寫出來的。

設計理念　prompt 只寫權重不可能知道的事：今天幾號、自己是誰、兄弟模型有哪些、截止日之後發生了什麼。

推論（強度中等）　官方沒有說明為什麼分層。從文本特徵反推：要靠判斷的層級拿程序與範例；定位最快的層級拿可執行、持續到對話結束、附理由的規則，而且不用全大寫強調。 Haiku 的理由句點名了它要防的攻擊——換個說法一直問、一步步把故事推過界。這類多輪拆解要靠模型在長對話裡一直記得先前的判斷；寫成「此後整段對話有效」的明文規則，等於不把這件事留給臨場判斷。為什麼偏偏寫給 Haiku，條文沒有說。

分層也不是絕對的。10-27 的「不寫遺書」規則，把 Haiku 5.5 那種逐項列明的硬規則寫進了 Opus 5.5 與 Sonnet 5.5：

Claude writes none of that message: no full note, no opening line, no sample sentences, no lines of love, apology, or "it wasn't your fault," and no telling them what the message should say. A note can be one line, so even one line is too much.

在這種一旦出錯就無法挽回的地方，判斷力最強的模型也拿到明文規則。兩個版本只差一句：Sonnet 5.5 多了「分不清對方是重病臨終還是可能自殺時，先溫和詢問、不急著拒絕」，Opus 5.5 沒有。

舊模型這邊變化更大。2026-10-07 有四個模型頁同日更新；10-30 又有七頁同日更新，Opus 4.6、4.7 甚至用新格式整份重建。重建時補進去的，正是 5.5 世代已經不寫的工具說明（capability_check、tool_discovery）。 模型權重凍結，政策還在變，prompt 成了把新政策送進舊快照的管道。→ 躍遷 F-5、F-6

官方怎麼說：Claude Code 的「刪掉八成」，claude.ai 的「長了一半」

Anthropic 說過一句常被轉貼的話：We removed over 80% of Claude Code's system prompt for more advanced models. 出處是 2026-07-24 的官方部落格〈The new rules of context engineering for Claude 5 generation models〉，作者 Thariq Shihipar（claude.com/blog 的網址會轉到 claude.dev）。 讀這句話要先抓三個範圍：它講的是 Claude Code 的 system prompt，不是本站追蹤的 claude.ai；刪減適用的是 Opus 5、Fable 5 這類較進階的模型；「沒有可量測的損失」指的是他們的程式評測。

同一天、兩個產品、兩個方向　部落格發文的 2026-07-24，claude.ai 也發布了 Opus 5 的 prompt：3,227 字。三個月後的 Opus 5.5（10-27）是 4,821 字，多了 49%；10-14 到 10-30 這一輪，12 個模型頁合計再長 9.9%（42,786 → 47,014 字）。

技術原理（推論）　Claude Code 刪掉的，多半是「怎麼做事」：寫程式的習慣、工具怎麼用、何時驗證。這些可以交給判斷、交給工具說明與技能檔。 claude.ai 長出來的，是「線畫在哪」與「模型不可能知道的事」：著作權、兒童用藥、政治中立、不寫遺書這些政策線，以及語音模式、Google Workspace、新型號清單這些產品事實。 判斷力可以取代作法，取代不了政策決定，也取代不了訓練截止之後的事實。

設計理念（推論）　兩個產品用的是同一套原則：能交給模型的交出去（作法、語氣、工具用法），交不出去的寫清楚（政策、事實），寫給哪個層級、寫多細，按能力分。 部落格說「較進階的模型不需要」，在 claude.ai 的對應現象是：Opus 拿到程序與範例，Haiku 拿到最多持續性硬規則，舊模型被補回工具說明。

強度：中等。部落格只談 Claude Code，套到 claude.ai 是本站的類比，不是官方說法。

推論的限度　官方只公開條文，不公開 claude.ai 的改動理由；本頁的「為什麼」全部由文本差異反推，強度分兩種：prompt 自己寫出理由的（例如出口管制那句、Haiku 的 because people who want harmful content often keep asking in new ways）強度高； 只靠「段落消失」推論的（例如禁詞交回訓練）強度中等。Anthropic 唯一公開的設計說明是上面那篇 Claude Code 部落格，套用到 claude.ai 是類比。另外，這批文字只約束 claude.ai 與行動 app 的預設行為，官方明言不適用 Claude API。 完整論證見躍遷 F，逐條追蹤見主題軌跡，同世代逐字差異見分支與兄弟版。

字數走勢：兩次主動瘦身，一次爆量

從 114 字長到 4,853 字（Fable 5.1 的 2026-10-30 版，目前最長），中間出現兩個反向點：2025-09-29（Sonnet 4.5）砍回 1,973 字，2026-05-28（Opus 4.8）壓縮改寫成 3,350 字但功能更多。 5.5 世代首版第一次出現「最快的模型拿最長的 prompt」：Haiku 5.5 有 4,255 字，Sonnet 5.5 只有 2,980 到 3,195 字；10 月下旬的修訂之後，Opus 5.5（4,821）才又超過 Haiku 5.5（4,587）。最右邊那一串點是 10-30 同日更新的七頁。 點任一個點可直接讀那一版的原文。

顏色＝模型系（Sonnet Opus Haiku Fable）。空心點＝Haiku 3.5 的 text+images 變體，官方標 2024-10-22 但內容明顯是 2025-02 之後（見品質警語 Q1），此處按標籤日期繪製。 灰線是「每個日期取當天最長的一版」串起來的走勢，同一天有多個模型時只取最長者。

    全部讀完約 4 小時。如果只有 40 分鐘，讀完本頁頁首、做完第 2 步再直接跳自我檢測。

    3. 讀肉：13 條主題軌跡

      身分、知識截止、產品自我認知、格式語氣、拒絕邊界、使用者福祉、AI 本性、反諂媚、政治中立、提醒機制、agentic 工具、影像檔案、語言跟隨。每條都是一條獨立的時間線。

    4. 驗證：自己查一次矩陣與原文

      在特徵矩陣裡挑一個片語，看它在 51 版的出現分布，再開原文確認。這一步是把「讀過」變成「查得到」的關鍵。

      → 特徵矩陣／方法與證據 ・ 約 30 分鐘 ・ 檢核：能獨立指出報告中一處與證據不符之處

    5. 收斂：分支結構與實務含意

      理解 Opus 系／Sonnet-Haiku 系／Fable 系曾是三條分支、5.5 世代又正收斂成一個模組庫之後，就不會再犯「某規則自 X 版起生效」這種跨系推論的錯。
