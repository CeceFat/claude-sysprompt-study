Claude 系統提示詞的兩年演進

Anthropic 會把 claude.ai 網頁與行動 app 使用的系統提示詞（system prompt）公開在官方發行說明頁上。 本站把 2024-07-12 到 2026-09-01、18 個模型頁、32 個版本的原文抓下來逐字比對， 整理成一套可自行查核的學習材料：每一條結論都能點回原文，每一句引文都能在證據包裡用字串搜到。

先講清楚適用範圍。官方明文寫著 These system prompt updates do not apply to the Claude API。 這批文字約束的是 claude.ai 與行動 app 的預設行為，不是 API 呼叫；也不是模型的訓練內容。 2025-11-19 之後，公開的甚至已經不是完整 prompt，而是組裝式 prompt 裡的一個行為組件——這點是讀懂後半段的關鍵。

字數走勢：兩次主動瘦身，一次爆量

從 114 字長到 4,267 字，中間出現兩個反向點：2025-09-29（Sonnet 4.5）砍回 1,973 字，2026-05-28（Opus 4.8）壓縮改寫成 3,350 字但功能更多。 點任一個點可直接讀那一版的原文。

顏色＝模型系（Sonnet Opus Haiku Fable）。空心點＝Haiku 3.5 的 text+images 變體，官方標 2024-10-22 但內容明顯是 2025-02 之後（見品質警語 Q1），此處按標籤日期繪製。

十行結論

先讀這十句，再決定要往哪一節鑽。每句都附上該去看的章節。

    建議學習路徑

    全部讀完約 3–4 小時。如果只有 40 分鐘，做完第 1、2 步再直接跳自我檢測。

    1. 建立座標：先看版本總表與字數走勢

      把 32 個版本的日期、模型系、字數、結構型態放進腦裡，之後任何一條規則都能定位到「哪一系、哪一版」。

      → 版本總表 ・ 約 25 分鐘 ・ 檢核：能說出哪三版是轉折點

    2. 抓骨架：五次架構躍遷

      單段落 → XML 三區塊 → 平鋪散文 → 散文加人格前言 → 全 schema 化 → agentic 作業規範。理解每次躍遷解決了什麼問題，比背條文有用。

      → 五次躍遷 ・ 約 35 分鐘 ・ 檢核：能說出 2025-09-29 一次刪掉了哪一類段落，以及為什麼

    3. 讀肉：13 條主題軌跡

      身分、知識截止、產品自我認知、格式語氣、拒絕邊界、使用者福祉、AI 本性、反諂媚、政治中立、提醒機制、agentic 工具、影像檔案、語言跟隨。每條都是一條獨立的時間線。

      → 主題軌跡 ・ 約 60 分鐘 ・ 檢核：任選一主題，說出它「加入 → 刪除 → 再出現」的完整歷程

    4. 驗證：自己查一次矩陣與原文

      在特徵矩陣裡挑一個片語，看它在 32 版的出現分布，再開原文確認。這一步是把「讀過」變成「查得到」的關鍵。

      → 特徵矩陣／方法與證據 ・ 約 30 分鐘 ・ 檢核：能獨立指出報告中一處與證據不符之處

    5. 收斂：分支結構與實務含意

      理解 Opus 系／Sonnet-Haiku 系／Fable 系是三條分支後，就不會再犯「某規則自 X 版起生效」這種跨系推論的錯。

      → 分支與兄弟版 ・ 約 25 分鐘 ・ 檢核：完成自我檢測 15 題

    怎麼讀這裡的引文

    引文

    襯線字體、左側色條的段落一律是官方原文逐字（英文），底下標座標〔模型頁／日期／區塊〕。可以在證據包裡用字串搜到；搜不到就是本站有錯，請開 issue。

    Claude defaults to helping.〔Opus 4.8 / 2026-05-28 / default_stance〕

    推論

    綠底標「推論」的是解讀，不是文件明文。刻意分開標示，是因為這類敘述的強度取決於證據；有些推論的唯一依據只是「某段被刪掉了」。

    推論　這些行為已被吸收進訓練，不再靠 prompt 維持。

    開始前先自問

    1. 你認為 system prompt 是「模型的規則」還是「產品的設定」？讀完後這個答案應該會變。
    2. 如果某條規則在 prompt 裡消失了，代表模型不再遵守它嗎？
    3. 當 Claude 說「我不能做 X」，那句話的來源可能有幾種？
