方法與證據

一份講「文件怎麼變」的整理，如果自己不能被查核就沒有價值。 這一頁交代資料怎麼來、哪裡不可靠、以及本站在轉成網頁時重跑了哪些查核。

資料怎麼來

  1. 以 curl 抓取 overview 與各模型子頁的 .md 原始檔（Mintlify 原始 MDX），不經任何摘要模型。2026-09-07 抓 overview＋18 頁；2026-10-28、2026-11-05 各重抓 overview＋22 頁；2026-11-10 重抓 overview＋23 頁（多了 Fable 5.2）。
    curl -sL -H "Accept: text/markdown" https://platform.claude.com/docs/en/release-notes/system-prompts/<slug>.md
  2. 依每頁的 ## <日期> 標題與 Text only: ／ Text and images: 標籤，把 ```text 圍欄內文切成版本檔：第一輪 34 個，10-28 新增 7 個，11-05 新增 12 個，11-10 新增 1 個，共 54 個。分析矩陣取 52 欄：Opus 4 的 2025-07-31、08-05 兩個條目與 Sonnet 4 同日版本只差名稱、定位語與 model string，不另列欄。同一條目被 MDX 切成多個圍欄時依序接回（Q6）。
  3. 以 git diff --no-index -U0 --word-diff=plain 做逐字比對（同頁相鄰日期、同日兄弟模型、跨世代承接），輸出 [-舊-]{+新+} 格式：第一輪 21 組，10-28 新增 11 組，11-05 新增 15 組，11-10 新增 4 組，共 51 組。
  4. 以關鍵片語對各版做出現矩陣（不分大小寫子字串比對），交叉驗證 diff 結論：第一輪 118 片語 × 32 欄以 PowerShell IndexOf(OrdinalIgnoreCase) 產生；10-28 改用 Python 重算，先確認舊 118 × 32 逐格重現，再追加 28 片語與 7 欄，共 146 × 39；11-05 再追加 20 片語與 12 欄，共 166 × 51；11-10 再追加 15 片語與 1 欄，共 181 × 52。每一輪都確認舊格子逐格不變。片語是子字串比對，短片語會命中包含它的較長句子。
  5. 10-28 起另做逐段血緣比對，算出各版「逐字沿用／小幅改寫／新寫」的比例，見下方血緣算法。

evidence/sources/ 是官方頁面原文（現存為 2026-11-10 版本）；versions/、diffs/、feature_matrix.txt 是分析產物；evidence/tools/ 是 10-28 起使用的腳本；evidence/external/ 記錄本站引用的官方部落格逐字句與出處（不存全文）。

血緣算法：「逐字沿用／小幅改寫／新寫」怎麼算

  1. 以「段落」為單位：版本檔裡一行就是一段（或一個條列項），比對前去掉首尾空白。
  2. 參照組＝該版發布日以前已公開的所有版本（同日的兄弟版不算參照）。
  3. 某段與參照組任一段完全相同＝逐字沿用；否則與參照組各段算 difflib.SequenceMatcher 相似度，最高 ≥ 0.8＝小幅改寫（多半是型號、日期、user → person）；其餘＝新寫。
  4. 比例以字數加權（空白切詞，與全站字數同一算法）。
  5. 「發布日」用的是官方條目上標的日期。Sonnet 5 的頁面是事後才上架的（Q9），仍照它標的 2026-06-30 排。

限制：門檻 0.8 是人為選定；段落被拆開或合併時會被算成新寫，所以「新寫」是上限估計。同日的兄弟版不算參照，所以同一天推到多頁的模組在每一頁都算新寫（Haiku 5.5 的 1,577 字若把同日兄弟版算進去是 1,360 字）。 Sonnet 3.5 的兩個 2024-10-22 版本檔各只有一行（見下方查核紀錄），裡面的段落無法與後來的版本逐段比對；四個帶 ** 差異標記的條目（Q4）裡，被標記的段落也不會和後來沒有標記的同一段算成逐字相同。這兩點只影響 2026-02 以前的版本，本頁表列的數字不受影響。

比較重要的更正

  • 舊模型「整份重建」不是 10-30 才開始。照同一個算法，10-07 的 Sonnet 4.6 只有 22.6% 逐字留自二月版，Haiku 4.5 只有 27.9% 留自一月版，和 10-30 的 Opus 4.6（15.4%）、Opus 4.7（24.5%）是同一個量級。前幾輪把 10-07 寫成「舊骨架加新模組」，低估了改動幅度。
  • 「判斷給 Opus、規則給 Haiku」的分層推論改弱。Fable 5.2 比 Opus 高階，拿到的是 Haiku 式的持續性規則。
  • 「5.5 世代的行為組件不談工具」寫得太滿。沒有的是工具作業區塊；兒童用藥段、出口管制通知、知識截止段都還留著「有網搜就查」這類條件句。
  • 三個「骨架」的說法寫得太滿。Opus 5 的文字是兩邊都取：逐字段落 48% 見於 Opus 4.8、46% 見於 Fable 5。Sonnet 5.5 見於 Opus 5.5 的（69%）比見於 Sonnet 5 的（56%）多。Opus 5.5 原本寫成「Opus 5 骨架＋Fable 5.1 模組」，其實見於 Fable 5.1 的（50%）比見於 Opus 5 的（37%）多，區塊的組成也和 Fable 5.1 相同。
  • 幾個「首見」寫晚了：語言跟隨規則是 2024-07（不是 Sonnet 3.7），反條列規則先見於 Haiku 3.5 的 2024-10-22，tool_search 是 Opus 4.7（不是 4.8），Claude is honest by default 是 Opus 5（不是 Fable 5.1）。
  • 兒童用藥段不是「同一段文字」：10-07 首發的四頁是四份文字，10-27 起才統一。
  • Opus 5.5 血緣拆分的兩個百分比（10.7%、25.9%）是截斷，應為 10.8%、26.0%。

查核工具本身也改了：verify_quotes.py 原本不分大小寫，現在改成區分大小寫；稽核用的獨立程式放在 evidence/tools/audit/，可以重跑。

Q2　2025-08-05 條目與 07-31 逐字相同

Sonnet 4 與 Opus 4 的 2025-08-05 條目與 2025-07-31 條目完全一致（diff 為空，本站已重跑確認）。

影響：08-05 只是 Opus 4.1 發布日的同步收錄，不是一次變更。把它當成「一次改版」會高估改版頻率。

Q3　網域被回溯改寫，URL 不能當年代證據

Haiku 3.5 的 text-only 變體已寫 support.claude.com／docs.claude.com，但同期的 Sonnet 3.5（2024-11-22）仍是 anthropic.com；claude.com 網域在其他頁首次出現於 2025-09-29。

影響：頁面曾被回溯做網域替換。用 URL 推斷條文年代會出錯。可在特徵矩陣搜 docs.anthropic.com 與 docs.claude.com 對照分布。

Q4　只有四個條目自己標了差異

只有 Sonnet 3.5 的 2024-09-09，以及 Sonnet 4.5、Haiku 4.5、Opus 4.5 的 2026-01-18，在頁首說明句中用 ** 標記與前版的差異。

影響：其餘差異必須自行 diff。這正是這份整理存在的理由。

Q5　Opus 4.6 的 election_info 失去格式

<election_info> 整段擠成一行，條列格式消失。

座標〔Opus 4.6 / 2026-02-05 / knowledge_cutoff〕　影響：顯示為手動貼回，不是流程產出。搭配它「刪除後又重現」的軌跡看，是分支手動維護的強證據。

Q6　頁面被 MDX 切成多塊（Fable 5.1、Opus 5.5、Sonnet 5、Fable 5.2）

Fable 5.1 頁在 <example> 處被切成兩個程式碼區塊；2026-10-28 重抓時 Opus 5.5 頁在同一位置以同樣方式被切開，Sonnet 5 頁則在 <proactivity> 前後被切成三塊。2026-11-10 抓到的 Fable 5.2 頁同樣在 <example> 處被切成兩塊。

  • If neither the child's age or weight is given（Sonnet 5.5 10-07、Haiku 5.5；同日的 Haiku 4.5、Sonnet 4.6 寫 nor。之後 10-27、10-30 的八個條目與 11-09 的 Fable 5.2 都沿用 or 的版本）
  • Haiku 4.5 的 2025-11-19 條目寫著 The person can access Claude Sonnet 4.5 with the model string 'claude-sonnet-4-5-20250929'，整句照搬 Sonnet 4.5 頁，沒有自己的 model string（10-15 條目原本兩個都列）

影響：錯字能存活數個版本、跨越數個模型，佐證 prompt 是人手逐段編修並在分支間複製貼上，而不是由單一來源產生。同一天、同一個新區塊在不同頁出現 or／nor 兩種寫法，也說明 <medical_guidance> 至少有兩個來源稿。

Q8　overview 刪掉自己的說法：「4.6 世代起一個模型一個條目」不再成立

2026-09-07 的 overview 寫著 Starting with the Claude 4.6 generation, each model ID is a single fixed snapshot, so those models have one entry.，2026-10-28 重抓時這句已刪（見 diff 31）。同時 Sonnet 4.6 頁多了 2026-10-07 條目，Sonnet 5.5 頁也有兩個條目（現在是三個）。

影響：模型權重固定，不代表 prompt 固定；舊模型仍會拿到新條目（本站稱為「回補」）。模型頁的條目數只反映官方頁面更新了幾次，不能拿來推論某模型的 prompt 有沒有變過。引用 overview 時要註明抓取日期。11-05 重抓時更明顯：12 個模型頁在 10 月下旬又多一個條目，連 2 月發布的 Opus 4.6 都有了第二個條目，而且新條目只有 15% 逐字留自前一版（10-07 的 Sonnet 4.6、Haiku 4.5 也只有 23%、28%）。

Q9　頁面事後上架：Sonnet 5（標 2026-06-30）在 09-07 快照時不存在

09-07 的 overview 沒有 Sonnet 5 這張卡片，但當時已公開的 Opus 5（07-24）與 Fable 5.1（09-01）都在模型清單裡寫了 claude-sonnet-5。10-28 重抓時 Sonnet 5 頁才出現，條目日期標 2026-06-30，內容寫的是出口管制「暫停中」，與那個日期吻合。

影響：發行說明不是即時同步的紀錄，頁面可以事後補上；「某版本在某日不在官方頁面上」不能推論它當時沒有部署。本站把它編為第 33 欄（依加入順序），在版本總表與走勢圖則依標註日期排序。

Q10　prompt 裡的「官方部落格引文」被改過型號

Opus 5（2026-07-24 起，含 10-30 的新條目）的 <fable_safeguards_routing> 說 Claude 可以 directly cite or just let its response be informed by this quote from Anthropic's blog post on the subject，引文中寫的是 receive a response from our next-most-capable model, Claude Opus 5。 06-09 的 Fable 5 發布文（2026-11-05 抓取，11-10 重抓確認）原句是 receive a response from our next-most-capable model, Claude Opus 4.8；10-30 新增同一段的 Opus 4.8 條目，引的正是這個原句。

影響：prompt 裡標示為「引文」的文字不一定逐字。推論是同一段範本代入了各模型自己的型號。引用 prompt 轉述的外部文件時要回頭對原始出處；本站的出處紀錄見 evidence/external/excerpts.txt。第一輪報告 §3.5 曾把 Opus 5 的版本當成官方原話引用，已在增補 §B 更正。

2026-11-10 補充：逐字比對後，Opus 5 條文裡那段引文和發布文只差這一個型號，其餘完全相同。另外，2026-11-09 的 Fable 5.2 發布公告寫明被安全分類器擋下的查詢 will instead receive a response from Opus 4.8 for cybersecurity and Opus 5 for biology，AI 研發領域另有 transparent fallbacks to Opus 5 for a small set of topics in this domain，所以 Opus 5 確實是路由目的地之一；但 06-09 那篇發布文的原句寫的是 Opus 4.8，標示為引文的那一句仍與原文不符。

Q11　overview 舉的例子早已不在條文裡

overview 至今寫著 system prompt also encourages certain behaviors, such as always providing code snippets in Markdown。公開條文裡要求用 Markdown 寫程式碼的句子（Claude uses markdown for code 一類）最後見於 Sonnet 3.7（2025-02-24），2025-05-22 的 Claude 4 起就沒有了。

影響：overview 的說明文字沒有跟著條文更新，不能拿來推論現行 prompt 的內容。這個行為現在由什麼負責，公開條文看不出來。本站測驗第 3 題的解析原本也寫錯（說這句「一直都在」），2026-11-10 更正。
