方法與證據

一份講「文件怎麼變」的整理，如果自己不能被查核就沒有價值。 這一頁交代資料怎麼來、哪裡不可靠、以及本站在轉成網頁時重跑了哪些查核。

資料怎麼來

  1. 以 curl 抓取 overview 與各模型子頁的 .md 原始檔（Mintlify 原始 MDX），不經任何摘要模型。2026-09-07 抓 overview＋18 頁；2026-10-28 重抓 overview＋22 頁。
    curl -sL -H "Accept: text/markdown" https://platform.claude.com/docs/en/release-notes/system-prompts/<slug>.md
  2. 依每頁的 ## <日期> 標題與 Text only: ／ Text and images: 標籤，把 ```text 圍欄內文切成版本檔：第一輪 34 個，10-28 新增 7 個，共 41 個（分析矩陣取 39 欄）。同一條目被 MDX 切成多個圍欄時依序接回（Q6）。
  3. 以 git diff --no-index -U0 --word-diff=plain 做逐字比對（同頁相鄰日期、同日兄弟模型、跨世代承接），輸出 [-舊-]{+新+} 格式：第一輪 21 組，10-28 新增 11 組，共 32 組。
  4. 以關鍵片語對各版做出現矩陣（不分大小寫子字串比對），交叉驗證 diff 結論：第一輪 118 片語 × 32 欄以 PowerShell IndexOf(OrdinalIgnoreCase) 產生；10-28 改用 Python 重算，先確認舊 118 × 32 逐格重現，再追加 28 片語與 7 欄，共 146 × 39。
  5. 10-28 另做逐段血緣比對，算出各版「逐字沿用／小幅改寫／新寫」的比例，見下方血緣算法。

evidence/sources/ 是官方頁面原文（現存為 2026-10-28 版本）；versions/、diffs/、feature_matrix.txt 是分析產物；evidence/tools/ 是 10-28 這一輪用的腳本。

血緣算法：「逐字沿用／小幅改寫／新寫」怎麼算

  1. 以「段落」為單位：版本檔裡一行就是一段（或一個條列項），比對前去掉首尾空白。
  2. 參照組＝該版發布日以前已公開的所有版本（同日的兄弟版不算參照）。
  3. 某段與參照組任一段完全相同＝逐字沿用；否則與參照組各段算 difflib.SequenceMatcher 相似度，最高 ≥ 0.8＝小幅改寫（多半是型號、日期、user → person）；其餘＝新寫。
  4. 比例以字數加權（空白切詞，與全站字數同一算法）。

九項文件品質警語

這些是官方文件本身的瑕疵，不是整理過程造成的。引用前先看一眼。

Q1　Haiku 3.5 的 text+images 變體，日期標籤不可信影響最大

該變體標在 2024-10-22 之下，內容卻寫著 The Claude 3 family currently consists of Claude Haiku 3.5, Claude Opus 3, Claude Sonnet 3.5, and Claude Sonnet 3.7、model string claude-3-7-sonnet-20250219、cutoff start of December 2024、網址 docs.claude.com。

座標〔Haiku 3.5 / 2024-10-22 / text+images〕　影響：該變體實為 2025-02 之後的 3.7 世代模板套用於 Haiku，日期標籤不可信。本站在版本表與矩陣中都把它排在第 12 位並加註。

Q2　2025-08-05 條目與 07-31 逐字相同

Sonnet 4 與 Opus 4 的 2025-08-05 條目與 2025-07-31 條目完全一致（diff 為空，本站已重跑確認）。

影響：08-05 只是 Opus 4.1 發布日的同步收錄，不是一次變更。把它當成「一次改版」會高估改版頻率。

Q3　網域被回溯改寫，URL 不能當年代證據

Haiku 3.5 的 text-only 變體已寫 support.claude.com／docs.claude.com，但同期的 Sonnet 3.5（2024-11-22）仍是 anthropic.com；claude.com 網域在其他頁首次出現於 2025-09-29。

影響：頁面曾被回溯做網域替換。用 URL 推斷條文年代會出錯。可在特徵矩陣搜 docs.anthropic.com 與 docs.claude.com 對照分布。

Q4　只有四個條目自己標了差異

只有 Sonnet 3.5 的 2024-09-09，以及 Sonnet 4.5、Haiku 4.5、Opus 4.5 的 2026-01-18，在頁首說明句中用 ** 標記與前版的差異。

影響：其餘差異必須自行 diff。這正是這份整理存在的理由。

Q5　Opus 4.6 的 election_info 失去格式

<election_info> 整段擠成一行，條列格式消失。

座標〔Opus 4.6 / 2026-02-05 / knowledge_cutoff〕　影響：顯示為手動貼回，不是流程產出。搭配它「刪除後又重現」的軌跡看，是分支手動維護的強證據。

Q6　頁面被 MDX 切成多塊（Fable 5.1、Opus 5.5、Sonnet 5）

Fable 5.1 頁在 <example> 處被切成兩個程式碼區塊；2026-10-28 重抓時 Opus 5.5 頁在同一位置以同樣方式被切開，Sonnet 5 頁則在 <proactivity> 前後被切成三塊。

影響：本站證據包把同一條目的多個區塊依序接回成單一 prompt（接縫處只加一個換行）。Fable 5.1 的 4,267 字、Opus 5.5 的 4,119 字、Sonnet 5 的 3,470 字都是接回後的數字。直接在官方頁面上複製其中一塊，會拿到不完整的 prompt。

Q7　長期未修的錯字，佐證人手編修
  • as as、being being（Opus 4.1 → 2026-01-18 才修）
  • can't or won't with（Claude 4 全期）
  • crises（Opus 4.5 起）
  • Claude can instead treats（至 Opus 4.7）
  • the left of the right（Haiku 3.5）
  • National Alliance for Eating Disorder（Opus 4.8 才補 s）
  • Claude can instead treats 在 Haiku 4.5 頁一直存活到 2026-01-18 條目，2026-10-07 回補條目才改成 treat，同時拿掉該頁的 ** 差異標記
  • If neither the child's age or weight is given（Sonnet 5.5 10-07、Haiku 5.5；同日的 Haiku 4.5、Sonnet 4.6 寫 nor）

影響：錯字能存活數個版本、跨越數個模型，佐證 prompt 是人手逐段編修並在分支間複製貼上，而不是由單一來源產生。同一天、同一個新區塊在不同頁出現 or／nor 兩種寫法，也說明 <medical_guidance> 至少有兩個來源稿。

Q8　overview 刪掉自己的說法：「4.6 世代起一個模型一個條目」不再成立

2026-09-07 的 overview 寫著 Starting with the Claude 4.6 generation, each model ID is a single fixed snapshot, so those models have one entry.，2026-10-28 重抓時這句已刪（見 diff 31）。同時 Sonnet 4.6 頁多了 2026-10-07 條目，Sonnet 5.5 頁也有兩個條目。

影響：模型權重固定，不代表 prompt 固定；舊模型仍會拿到新條目（本站稱為「回補」）。模型頁的條目數只反映官方頁面更新了幾次，不能拿來推論某模型的 prompt 有沒有變過。引用 overview 時要註明抓取日期。

Q9　頁面事後上架：Sonnet 5（標 2026-06-30）在 09-07 快照時不存在

09-07 的 overview 沒有 Sonnet 5 這張卡片，但當時已公開的 Opus 5（07-24）與 Fable 5.1（09-01）都在模型清單裡寫了 claude-sonnet-5。10-28 重抓時 Sonnet 5 頁才出現，條目日期標 2026-06-30，內容寫的是出口管制「暫停中」，與那個日期吻合。

影響：發行說明不是即時同步的紀錄，頁面可以事後補上；「某版本在某日不在官方頁面上」不能推論它當時沒有部署。本站把它編為第 33 欄（依加入順序），在版本總表與走勢圖則依標註日期排序。
